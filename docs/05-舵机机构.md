# 05 舵机机构

## 舵机运动（单一）

**功能描述**：一个模拟舵机，信号线接 PB9，通过 PS2 手柄的「×」键在两个预设角度之间切换，用于驱动后续的收集/抬升机构。

### 硬件与引脚

| 项目 | 内容 |
| --- | --- |
| 信号线 | PB9（TIM4_CH4） |
| 供电 | 舵机电源独立于 MCU 3.3 V，共地 |
| 控制方式 | 50 Hz PWM，脉宽 0.5~2.5 ms 对应 0~180° |

### 时基设计

舵机对脉宽的要求是「周期 20 ms、高电平 0.5~2.5 ms」。为了让占空比寄存器直接就是微秒数，时基按 1 MHz 设计：

```
TIM4 时钟 = 72 MHz（APB1 定时器倍频）
PSC = 72 - 1        → 计数频率 1 MHz，1 个计数 = 1 μs
ARR = 20000 - 1     → 周期 20000 μs = 20 ms = 50 Hz
CCR = 脉宽微秒数     → 500 ~ 2500 直接对应 0 ~ 180°
```

```cpp
sConfigOC.Pulse = angle_to_pulse(angle);
__HAL_TIM_SetCompare(&htim4_servo, TIM_CHANNEL_4, angle_to_pulse(degree));
```

**为什么不让 CCR 按 0~1000 之类的「百分比」来写**：舵机的有效区间只有 500~2500 μs，如果按占空比百分比映射，调试时要不停换算成微秒去对照手册。直接用 1 μs 计数，CCR 的数值就是脉宽本身，示波器和逻辑分析仪上量到多少、代码里就是多少，排查时省一步换算。

### 按键触发方式

```c
uint16_t btn = ~(raw.buttonLow | (raw.buttonHigh << 8));
uint8_t pressed = (btn & SERVO_BTN_MASK) ? 1 : 0;
if (pressed && !servo_btn_prev) {
    servo_toggle();       /* 只在上升沿切换一次 */
}
servo_btn_prev = pressed;
```

**为什么必须做边沿检测**：主循环 50 Hz，一次按键会持续几十到几百毫秒，也就是被读到十几到几十次。如果直接判断电平，按一下舵机会来回翻转十几次，最后停在哪一侧完全随机。改成「本次按下且上次没按」的上升沿判断后，一次按压只触发一次切换。

### 两个预设角度

```c
#define SERVO_ANGLE_A 30.0f
#define SERVO_ANGLE_B 150.0f
```

上电时舵机停在 **90°（中位）**，第一次按键去 30°，第二次去 150°，如此往复。选 30°/150° 而不是 0°/180° 是为了避开舵机的机械极限——大部分舵机标称 180° 但实际两端会顶住限位，长期顶死会堵转发热。实际行程需按机构调整这两个宏。

## 开发历程

**选 TIM4 而不是软件延时**：舵机要求持续输出 50 Hz 脉冲，如果用 `HAL_Delay` 加 GPIO 翻转，主循环会被占满，手柄就没法读了。TIM4 的 PWM 由硬件产生，CPU 只需要在切换角度时改一次 CCR，其余时间完全不占用。

**和电机 PWM 分开的原因**：电机用 TIM1（20 kHz），舵机用 TIM4（50 Hz），两者的预分频和重装值相差极大，没法共用一个定时器。分开还有一个好处——调电机的频率不会影响舵机脉宽。

**PB9 的复用关系**：F103 上 PB9 默认就是 TIM4_CH4，不需要重映射，也不与电机的 PA8~PA11、PS2 的 PA4~PA7 冲突。原理图上 PB7/PB8/PB9 标注为 SIG2/SIG3/SIG4 的空网络，正好可以用来接舵机信号。

## 当前状态与待验证项

代码已实现并编译通过（FLASH 约 13.3 KB / 20.3%），等待实测。

1. **舵机是否抖动**：若上电后一直轻微抖动，多为供电不足，需要给舵机单独供电并与 MCU 共地；
2. **角度方向**：若 30° 和 150° 的实际位置与预期相反，把两个宏对调即可；
3. **行程范围**：首次测试建议先用手轻扶舵机臂，确认不会顶到机构限位再放开。
