# 02 底盘运动

## 电机运动（全部）

**功能描述**：四只 TT 减速电机同时转动，转速由各自独立的 PWM 通道控制，转向由各自的方向脚决定。

**实现要点**：

1. `chassis_init()` 做板级初始化——PB0/PB1 拉高使能两颗驱动芯片，PB12~PB15 拉低设为「正转」；
2. TIM1 CH1~CH4 配置为 PWM1 模式，20 kHz，四通道占空比起始为 0；
3. 置位 MOE 后依次 `HAL_TIM_PWM_Start` 四个通道；
4. 主循环 `chassis_move(3600, 0, 0)` 把四路 CCR 写满，四轮满占空比转动。

**验证结果**：四只电机同时转动、方向一致，无一失效。

**演示视频**：[`media/chassis-motion.mp4`](media/chassis-motion.mp4)
参数 H.264 / 1280×720 / 30 fps / 9.03 s / 2.5 MB；⚠️ 低于手册要求的 1080p，正式提交前需重拍。

**调试历程**：第一次联调四轮不转。先用 ST-LINK 读回寄存器确认 CCR 已写入 3600（软件逻辑无误），再查 GPIO 发现 PA8~PA11 未配置成复用推挽，PWM 出不了引脚；补上后仍无波形，最终定位到 **TIM1 的 MOE 位未置位**——高级定时器即使使能 CC 通道，只要 BDTR.MOE = 0 输出端就是死的，这一点与通用定时器不同。

## 底盘运动（全部）：麦轮全向移动

**目标功能**：用 PS2 手柄控制车体的水平运动（前进、后退、左右横移、原地旋转）。

本车使用**麦克纳姆轮**，四轮独立驱动，通过转速组合实现全向移动。

### 麦轮逆运动学

```cpp
void ChassisCtrl::update_mecanum(float vx, float vy, float w) {
  float fl = vx - vy - w;
  float fr = vx + vy + w;
  float bl = vx + vy - w;
  float br = vx - vy + w;
  /* 超量程时等比缩放，保证合速度方向不变 */
  ...
  _m[0].set_speed((int16_t)fl);   // 左前 FL
  _m[1].set_speed((int16_t)fr);   // 右前 FR
  _m[2].set_speed((int16_t)bl);   // 左后 BL
  _m[3].set_speed((int16_t)br);   // 右后 BR
}
```

`vx > 0` 前进，`vy > 0` 右移，`w > 0` 逆时针自转。符号规律可以这样记：**前进时四轮同向；横移时对角线同向、相邻轮反向；自转时左右两侧反向。**

| 动作 | (vx, vy, w) | FL | FR | BL | BR |
| --- | --- | --- | --- | --- | --- |
| 前进 | (1, 0, 0) | + | + | + | + |
| 后退 | (-1, 0, 0) | − | − | − | − |
| 右移 | (0, 1, 0) | − | + | + | − |
| 左移 | (0, -1, 0) | + | − | − | + |
| 逆时针 | (0, 0, 1) | − | + | − | + |
| 顺时针 | (0, 0, -1) | + | − | + | − |

**为什么要等比缩放**：斜向移动时 `vx` 与 `vy` 同时非零，单轮合成速度可能超过 ±3600。若简单截断，四轮比值被破坏、车会走偏；等比缩放保持各轮比例，方向不变、整体降速。

### PS2 手柄遥控（当前固件）

手柄通过软件模拟 SPI 时序读取（板上引脚顺序与 SPI1 硬件功能不兼容，详见文档 [03](./03-PS2手柄遥控.md)），主循环以 50 Hz 读取并映射到麦轮：

| 输入 | 动作 | 参数 |
| --- | --- | --- |
| 左摇杆 ↑ / ↓ | 前进 / 后退 | `vx = -(ly - 128) × 28.1` |
| 左摇杆 ← / → | 左移 / 右移 | `vy = (lx - 128) × 28.1` |
| 右摇杆 ← / → | 逆时针 / 顺时针 | `w = -(rx - 128) × 14.1` |

```c
#define JOY_CENTER 128
#define JOY_DEADZONE 12
#define JOY_SCALE (3600.0f / 128.0f)
#define W_SCALE (1800.0f / 128.0f)
#define CTRL_PERIOD_MS 20U
#define PS2_LOST_LIMIT 5U

chassis_move(-(float)ly * JOY_SCALE,
              (float)lx * JOY_SCALE,
             -(float)rx * W_SCALE);
```

旋转降半速，是因为原地旋转时四轮反向转动、实际线速度是轮速的两倍，满速很难控；死区 ±12 滤掉摇杆回中抖动；连续 5 次读帧失败则输出零速度，避免手柄断连后保持最后速度冲出去。

**开发历程**：解算先在**固定序列轮播**下验证——主循环按 前 → 后 → 左 → 右 循环，每方向 3 秒、间隔 5 秒，序列写死不随机，便于复现与录制。确认四向轮速组合正确后，才把手柄输入接上来替换轮播。保留轮播代码的价值在于：手柄通讯异常时，可用它作为已知正确的参考，快速区分问题出在「运动学」还是「通信」。

**当前状态**：解算与遥控代码均已实现并编译通过（FLASH 约 13.3 KB / 20.3%），已录制实拍视频（[`media/chassis-remote-01/02.mp4`](media/chassis-remote-01.mp4)），等待实测确认方向。若左右横移或旋转与操作相反，只需把对应符号取反，无需改接线。手册要求「车体与 PS2 手柄同时出镜」才计入指标，因此「底盘运动（单一 / 全部）」需实测确认后再提交。

## 关键实现细节

### 速度限幅与死区

```cpp
#define PWM_PERIOD 3600U
#define MOTOR_DEADZONE 28
```

限幅到 ±3600 防止解算溢出；**±28 死区**内部直接输出 0——占空比过低时电机堵转不转、持续发热并啸叫，死区既保护电机也消除噪声。

### 符号-幅值控制

`Motor::set_speed()` 把速度拆成「方向 + 幅值」：

| 输入 | IN1 (PWM) | IN2 (GPIO) | 结果 |
| --- | --- | --- | --- |
| `speed > +28` | `speed` | 低 | 正转，可调速 |
| `speed < -28` | `\|speed\|` | 高 | 反转，可调速 |
| `\|speed\| ≤ 28` | `0` | 低 | 停转 |

同一时刻只有一路 PWM 工作，另一路固定为低，不会出现两路同时为高的直通状态。

### 单侧转向翻转

原理图上右侧电机的 O1/O2 在排针上顺序与左侧相反（H2/H4 的 6、7 脚），若排线 1:1 直通，右侧车轮会与左侧反转。`Motor` 因此提供软件翻转开关：

```cpp
_m[1].set_reversed(true);   // 右前轮反向，无需改接线
```

装配后才发现某侧反了，只需改一行代码，不用拆车。

## 问题记录

| 问题 | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 四轮不转 | PWM 无输出 | PA8~PA11 未配成 AF_PP；TIM1 未置 MOE | 补复用配置 + `__HAL_TIM_MOE_ENABLE` |
| 右侧两轮不转 | 只有左前左后有反应 | 构造函数写成 `_m[4] = ...`，数组只有 4 个元素，越界写入；`_m[3]` 保持空指针 | 改为 `_m[3]` |
| 转向方向错乱 | 差速解算时前后轮不一致 | 左右分组写错（曾把 FL+FR 归为左、BL+BR 归为右） | 改为 FL+BL 为左、FR+BR 为右 |
| PWM 打到 PS2 线上 | 波形出现在 PA6/PA7 | 原固件沿用 TIM3(PA6/PA7/PB0/PB1) | 改用 TIM1，停用 `MX_TIM3_Init` |

越界那个 bug 值得单记：`_m[4]` 越界属于未定义行为，编译器不报错、运行时也不立刻崩溃，而是悄悄写到对象之后的内存，第四只电机始终是空指针，一旦 `set_speed()` 就解引用空 `TIM_HandleTypeDef*` 触发 HardFault。靠读代码很难发现，最后是逐个核对四路初始化才找出来的。
