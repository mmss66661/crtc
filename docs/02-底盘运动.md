# 02 底盘运动

## 电机运动（全部）

**功能描述**：四只 TT 减速电机可同时转动，且每只电机的转速由独立的 PWM 通道控制，转向由各自的方向脚独立决定。

**实现要点**：

1. `chassis_init()` 先做板级初始化——PB0/PB1 拉高使能两颗驱动芯片、PB12~PB15 拉低设定为「正转」方向；
2. 配置 TIM1 的 CH1~CH4 为 PWM1 模式，20 kHz，四通道占空比全部起始为 0；
3. 置位 MOE 使能主输出，再依次 `HAL_TIM_PWM_Start` 四个通道；
4. 主循环中 `update(3600, 0)` 把四路 CCR 全部写满，四轮满占空比转动。

**验证结果**：四只电机同时转动，方向一致，无一例失效。见下方视频。

**演示视频**： [`media/chassis-motion.mp4`](media/chassis-motion.mp4)

**开发历程**：

第一次联调时四轮完全不转。排查顺序是「先确认软件在做什么，再确认硬件收到了什么」：

- 先用 ST-LINK 连上读回寄存器，确认 TIM1 的 CCR 确实被写入了 3600 —— 说明软件逻辑没问题；
- 再查 GPIO 模式，发现 PA8~PA11 没有被配置成复用推挽输出，PWM 根本出不了引脚；
- 补上复用配置后仍然没波形，最后定位到 **TIM1 的 MOE 位没有置位**。高级定时器的 CC 通道即使使能，只要 BDTR.MOE = 0，输出端就是死的。这一点和通用定时器（TIM2/TIM3）的行为不同，容易忽略。

## 底盘运动（全部）—— 遥控部分开发中

**目标功能**：用 PS2 手柄控制全部车体的水平运动（前进、后退、原地转向）。

**差速解算**：已实现并可通过代码验证。

```cpp
void ChassisCtrl::update(float v, float turn) {
  int16_t left_speed  = (int16_t)(v - turn / 2.0f);
  int16_t right_speed = (int16_t)(v + turn / 2.0f);

  _m[0].set_speed(left_speed);   // 左前 FL
  _m[1].set_speed(right_speed);  // 右前 FR
  _m[2].set_speed(left_speed);   // 左后 BL
  _m[3].set_speed(right_speed);  // 右后 BR
}
```

- `v` 为线速度，正值前进；
- `turn` 为转向量，正值右转；
- 两侧差速实现转向，不需要额外的转向机构。

**当前状态**：解算层已就绪，但**手柄输入尚未接通**，因此「底盘运动（单一/全部）」两项指标本次未提交。阻塞点见文档 03。

## 关键实现细节

### 速度限幅与死区

```cpp
#define PWM_PERIOD 3600U
#define MOTOR_DEADZONE 28
```

- 限幅到 ±3600（满占空比），防止摇杆或解算溢出；
- **±28 的死区**：占空比过低时电机堵转但不转，会持续发热并发出啸叫。死区内直接输出 0，既保护电机也避免噪声。

### 符号-幅值控制

`Motor::set_speed()` 把速度拆成「方向 + 幅值」两部分：

| 输入 | IN1 (PWM) | IN2 (GPIO) | 结果 |
| --- | --- | --- | --- |
| `speed > +28` | `speed` | 低 | 正转，可调速 |
| `speed < -28` | `|speed|` | 高 | 反转，可调速 |
| `|speed| ≤ 28` | `0` | 低 | 停转 |

好处是同一时刻只有一路 PWM 在工作，另一路固定为低电平，不会出现两个输入同时为高的直通状态。

### 单侧转向翻转

原理图上右侧电机的 O1/O2 在排针上的顺序与左侧相反（H2 的 6/7 脚、H4 的 6/7 脚），如果驱动板排线是 1:1 直通，右侧车轮的实际转向会与左侧相反。为此 `Motor` 提供了软件翻转开关：

```cpp
_m[1].set_reversed(true);   // 右前轮反向，无需改接线
```

这样即使装配后才发现某侧反了，也只需要改一行代码，不用拆车。

## 开发历程与问题记录

| 问题 | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 四轮不转 | PWM 无输出 | PA8~PA11 未配成 AF_PP；TIM1 未置 MOE | 补复用配置 + `__HAL_TIM_MOE_ENABLE` |
| 右侧两轮不转 | 只有左前左后有反应 | `ChassisCtrl` 构造函数写成 `_m[4] = ...`，数组只有 4 个元素，越界写入；`_m[3]` 保持默认构造的空指针 | 改为 `_m[3]` |
| 转向时方向错乱 | 差速时前后轮转向不一致 | 左右分组写错（曾把 FL+FR 归为左、BL+BR 归为右） | 改为 FL+BL 为左、FR+BR 为右 |
| PWM 打到 PS2 线上 | 波形出现在 PA6/PA7 | 原固件沿用 TIM3(PA6/PA7/PB0/PB1) | 改用 TIM1，停用 `MX_TIM3_Init` |

**越界那个 bug 值得单独说**：`Motor _m[4]` 的合法下标是 0~3，写成 `_m[4]` 时编译器不会报错（数组退化为指针后越界访问属于未定义行为），运行时也不会立刻崩溃，而是悄悄把数据写到对象之后的内存里。结果是第四只电机始终是空指针，一旦调用 `set_speed()` 就会解引用空 `TIM_HandleTypeDef*`，触发 HardFault。这类问题靠看代码很难发现，是后来逐个核对四路初始化才找出来的。
