# 04 开发日志与问题排查

按时间顺序记录工程演进：每个阶段做了什么、为什么这么选、遇到什么问题。

## 阶段一：工程搭建（9 月上旬）

- STM32CubeMX 建立 `CRTC_CAR_DEMO.ioc`，配置时钟树（HSE 8 MHz × PLL9 = 72 MHz）、GPIO、TIM2/TIM3、SPI1；
- 选 **CMake + Ninja** 而非 IDE 工程，保证任何机器拉下代码即可命令行编译；
- 建立分层目录：`Core/`（HAL 初始化）、`Chassis/`（电机控制 + 差速解算）、`PS2/`（手柄驱动）、`cmake/`（构建目标）。

选 C + C++ 混合，是因为 HAL 与 CubeMX 生成 C 代码，而电机、手柄这类有状态外设用类封装更清晰（构造时绑定定时器与通道，不必到处传句柄）；通过 `extern "C"` 导出 `chassis_init()` / `update()` / `PS2_Init()`，两侧互不干扰。

## 阶段二：电机与底盘驱动（9 月中旬）

- 实现 `Motor` 类（PWM 通道 + 方向控制，封装正反转与限幅）与 `ChassisCtrl`（四电机差速解算）；
- 编译通过，占用 RAM 1920 B / FLASH 15496 B。此时**代码从未在实物上验证**，引脚沿用了通用开发板的习惯。

## 阶段三：实物联调与引脚纠偏（10 月 17 日）

### 问题一：构建缓存被 IDE 污染

CLion 用自己的 MinGW 工具链重新 configure，`build/Debug/CMakeCache.txt` 里写满 `E:/CLion 2026.2.2/bin/mingw` 路径，导致 `arm-none-eabi-gcc` 构建直接失败。

**解决**：废弃被污染的缓存，显式指定工具链文件与 Ninja 重新配置。经验是交叉编译工程的构建目录与工具链强绑定，被 IDE 的本地编译器碰过之后删掉重建最省事，不要试图修补缓存。

### 问题二：ST-LINK 连不上，报 `Unable to get core ID`

CLI 报 `Voltage : 0.00V` 或 `1.36V`，且多次尝试间随机跳变（0.00 / 0.49 / 1.36 / 1.37），从未到 3.3 V。

**排查**：先后试了 `mode=UR`、`mode=hotplug`、把 `freq` 从 4 MHz 降到 100 kHz，现象完全一致，排除时序问题；电压读数不稳定说明不是软件问题；换用另一只 ST-LINK 并确认目标板供电后读到 `3.09V`，一次连接成功。

**结论**：`Voltage` 是 ST-LINK 从目标板 VREF 引脚实测的电压，STM32F103 最低工作电压 2.0 V。显示 0.00 V 或 1.x V 且随机跳变时，说明目标板未正常供电或 SWD 地线未导通，调连接参数不可能连上。

### 问题三：四轮不转 —— 引脚与 PCB 完全错位

逐脚核对原理图后发现原固件的三组功能全部对不上：

| 原固件使用 | 板上实际功能 |
| --- | --- |
| TIM2 → PA0~PA3 | 空脚 |
| TIM3 → PA6/PA7 | PS2 的 CS / CLK |
| TIM3 → PB0/PB1 | STBY1 / STBY2 |
| SPI1 重映射 → PB3~PB6 | 空脚 |
| — | 电机实际接 PA8~PA11（IN1）、PB12~PB15（IN2） |

**解决**：板级初始化从 `tim.c` 剥离到 `Chassis.cpp`——TIM1 CH1~CH4 输出 PWM 到 PA8~PA11，PB12~PB15 做方向，PB0/PB1 拉高使能，同时停用 `MX_TIM2_Init` / `MX_TIM3_Init` / `MX_SPI1_Init`。

**代价**：`.ioc` 未同步，此后不能用 CubeMX 重新生成代码，属当前技术债；长期应在 CubeMX 中按新引脚重配一次并替换手工初始化。

### 问题四：`_m[4]` 数组越界

`ChassisCtrl` 的成员是 `Motor _m[4]`，构造函数却写成 `_m[4] = Motor(...)`。合法下标只有 0~3，这一行是未定义行为：数据写到对象之后的内存，真正的 `_m[3]` 保持空指针，第四只电机一调用 `set_speed()` 就解引用空 `TIM_HandleTypeDef*` 触发 HardFault。编译器不报错、运行时不立刻崩，属典型静默错误。修正为 `_m[3]`。

### 问题五：左右轮分组错误

初版把 FL+FR 归为「左」、BL+BR 归为「右」，实际应为 **FL+BL 为左、FR+BR 为右**。直线时四轮速度相同看不出问题，一旦差速转向前后轮就打架。已修正。
