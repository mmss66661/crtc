# 01 整体方案与硬件设计

## 机器人整体方案

本机器人定位为 CRTC2026 的**资源争夺型轮式底盘**，目标是完成「电机运动」「底盘运动」「方块携带」三类基础功能，并为后续的收集机构预留接口。

整机采用 **四轮独立驱动 + 差速转向** 的方案：

- 4 个直流减速电机（TT 马达）分别驱动四个车轮，左右两侧各两只；
- 每只电机由一路双 H 桥驱动的 IN1/IN2 控制正反转，IN1 输入 PWM 调速；
- 转向不依赖舵机，而是通过左右两侧速度差实现（`left = v - turn/2`，`right = v + turn/2`）；
- 主控为 STM32F103C8T6 核心板，通过 8 针排线与驱动板、电机端子连接。

**为什么选差速而不是麦轮**：差速方案对四个电机的转速一致性要求低，调试阶段只需要保证四轮同向即可跑直，容错高；麦克纳姆轮虽然能横移，但需要四轮转速精确标定，在还没有编码器闭环的阶段反而更难调稳。当前代码结构（`ChassisCtrl::update(v, turn)`）已经把运动学解算隔离在单独一层，后续换成麦轮解算只需替换这一个函数，不影响底层驱动。

### 硬件构成

| 模块 | 型号 / 规格 | 说明 |
| --- | --- | --- |
| 主控 | STM32F103C8T6 核心板（40 pin 排针版） | Cortex-M3，64 KB Flash / 20 KB SRAM，72 MHz |
| 电机 | TT 直流减速电机 ×4 | 官方物资表指定，1:48 |
| 驱动 | 双 H 桥模块 ×2（IN1/IN2 + STBY 接口） | 官方物资表推荐 DRV8833，接口定义兼容 TB6612 |
| 手柄 | PS2 无线手柄 + 直插转接板 | 2.4G 无线，SPI 时序 |
| 调试 | ST-LINK V2 | SWD 四线 |
| 电源 | 2 × 18650 电池盒 + DC-DC 降压模块 | 电池组供电，降压出 5 V |

## 主控最小系统与时钟

- **时钟**：HSE 8 MHz 外部晶振，PLL ×9 → **SYSCLK 72 MHz**；AHB 72 MHz、APB1 36 MHz、APB2 72 MHz。
- **调试口**：SWD（PA13 = SWDIO，PA14 = SWCLK），已通过 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 关闭 JTAG 释放 PB3/PB4/PB5。
- **工程组织**：STM32CubeMX 生成初始化骨架，CMake + Ninja 构建，工具链为 STM32CubeCLT 自带的 `arm-none-eabi-gcc 13.3.1`。

**为什么用 CubeMX + CMake 而不是纯寄存器工程**：CubeMX 能保证时钟树、HAL 配置的正确性，把精力留给业务逻辑；CMake + Ninja 相比 IDE 工程更容易在 CI 或命令行复现，提交到仓库后任何人 `cmake --build` 即可编译，不依赖本地 IDE 配置。

## 电机驱动与引脚分配

驱动模块每个通道有 IN1、IN2 两根控制线和一个 STBY 使能脚。本设计的接法是：

- **IN1 接定时器 PWM 通道**，负责调速；
- **IN2 接普通 GPIO**，只做方向（高 = 反转，低 = 正转）；
- **STBY 接 GPIO 并上电拉高**，否则驱动芯片处于待机、输出全关。

这是「符号-幅值」控制方式：电机转速由 IN1 占空比决定，转向由 IN2 电平决定，同一时刻只有一路 PWM 在动，逻辑简单且不会出现两路同时导通的直通风险。

| 电机 | IN1（PWM） | IN2（方向） | 位置 |
| --- | --- | --- | --- |
| FL 左前 | PA8 / TIM1_CH1 | PB12 | 车头左侧 |
| FR 右前 | PA9 / TIM1_CH2 | PB13 | 车头右侧 |
| BL 左后 | PA10 / TIM1_CH3 | PB14 | 车尾左侧 |
| BR 右后 | PA11 / TIM1_CH4 | PB15 | 车尾右侧 |

| 使能 | 引脚 | 覆盖范围 |
| --- | --- | --- |
| STBY1 | PB0 | 前级驱动（FL + FR） |
| STBY2 | PB1 | 后级驱动（BL + BR） |

PWM 参数：TIM1，预分频 0，自动重装 3599 → **72 MHz / 3600 = 20 kHz**。选 20 kHz 是因为它高于人耳听觉上限，电机不会发出刺耳的啸叫；同时周期足够细（3600 级），低速段的占空比分辨率够用。

> **注意**：TIM1 属于高级定时器，除启动 PWM 外还必须置位 **MOE（主输出使能，BDTR 寄存器）**，否则四路 CC 通道全部没有波形。这是调试时最容易被忽略的一点。

## 电源与接口定义

### 电源

- 电池组（2 × 18650）经 XT30 / 杜邦接头输入，板上标注为 `+12V` 与 `GND`；
- 板载 `+5V` 供 PS2 接收器，`+3.3V` 供主控；
- 按手册 3.2 要求，整机只有**一个供电模块**，且额定电压不超过 7.4 V；无线继电器串在电池与底盘电源之间，用于 10 m 内独立切断动力。

> ⚠️ 待办：板面丝印标的是 `+12V`，而 2 节 18650 标称 7.4 V（满电 8.4 V）。接线前需确认板上是否有升压环节，避免误接 12 V 电源烧毁降压模块。

## 开发历程：从「照抄常见接法」到对齐实物

工程最初是按最常见的 STM32F103 最小系统板（“蓝板”）习惯配置的：

- 电机 PWM 用 TIM2 的 PA0~PA3 和 TIM3 的 PA6/PA7/PB0/PB1；
- PS2 用 SPI1 重映射到 PB3/PB4/PB5，片选 PB6。

这套配置在通用开发板上很常见，但在**本队实际打样的这块板子上完全对不上**。拿到 PCB 后逐脚核对发现：

1. 板上的 PB3/PB4/PB5/PB6 是**空脚**，根本没引出功能；
2. PA6/PA7 接的是 PS2 的 CS 和 CLK，被 TIM3 的 PWM 占用了；
3. PB0/PB1 接的是 STBY1/STBY2，同样被 TIM3 占用；
4. 电机驱动实际接在 PA8~PA11（IN1）和 PB12~PB15（IN2）上。

也就是说，按原配置烧进去，PWM 波形全打在 PS2 通讯线和驱动使能脚上，而真正该转的四个电机拿不到任何信号。

**修正方式**：把电机驱动层从 CubeMX 的 `tim.c` 里独立出来，改由 `Chassis/Src/Chassis.cpp` 自行完成板级初始化——TIM1 四通道 PWM 输出到 PA8~PA11，PB12~PB15 配为推挽输出做方向，PB0/PB1 拉高使能。同时停用 `MX_TIM2_Init` / `MX_TIM3_Init` / `MX_SPI1_Init`，避免重新占用这些引脚。

**为什么选择改软件而不是改硬件**：PCB 已经打样，改板成本远高于改固件；而 STM32 的定时器与引脚组合足够灵活，TIM1 的四个通道正好能满足四路独立调速的需求。

**踩过的坑**：`.ioc` 文件仍保留旧的引脚配置，若此时用 CubeMX 重新生成代码，会把 PA6/PA7/PB0/PB1 重新配回 TIM3 并覆盖上述修正。因此当前工程约定为**不重新生成、只手工维护 `Chassis/` 目录**，这一点也写进了根目录 README。
