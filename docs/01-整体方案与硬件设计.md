# 01 整体方案与硬件设计

## 机器人整体方案

本机器人定位为 CRTC2026 的**资源争夺型轮式底盘**，目标是完成「电机运动」「底盘运动」「方块携带」三类基础功能，并为后续的收集机构预留接口。

整机采用 **四轮独立驱动 + 差速转向**：

- 4 个 TT 直流减速电机分别驱动四个车轮，左右两侧各两只；
- 每只电机由一路双 H 桥的 IN1（PWM）调速、IN2（GPIO）定方向；
- 转向靠左右两侧速度差实现：`left = v - turn/2`，`right = v + turn/2`；
- 主控为 STM32F103C8T6，经 8 针排线连接驱动板与电机端子。

选差速而非麦轮，是因为差速对四轮转速一致性要求低，调试阶段只需保证四轮同向即可跑直；麦轮需要转速精确标定，在没有编码器闭环时反而更难调稳。运动学已隔离在 `ChassisCtrl::update(v, turn)` 一层，后续换麦轮只需替换该函数。

### 硬件构成

| 模块 | 型号 / 规格 | 说明 |
| --- | --- | --- |
| 主控 | STM32F103C8T6 核心板（40 pin 排针版） | Cortex-M3，64 KB Flash / 20 KB SRAM，72 MHz |
| 电机 | TT 直流减速电机 ×4 | 官方物资表指定，1:48 |
| 驱动 | 双 H 桥模块 ×2（IN1/IN2 + STBY） | 官方物资表推荐 DRV8833，接口兼容 TB6612 |

| 电源 | 电池组 + 板载两级降压 | Buck 出 5 V，LDO 出 3.3 V（见文档 [08](./硬件开发记录.md)） |

## 主控最小系统与时钟

- **时钟**：HSE 8 MHz，PLL ×9 → **SYSCLK 72 MHz**（AHB 72 / APB1 36 / APB2 72）；
- **调试口**：SWD（PA13 = SWDIO，PA14 = SWCLK），已用 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 关闭 JTAG 释放 PB3/PB4/PB5；
- **工程组织**：CubeMX 生成初始化骨架，CMake + Ninja 构建，工具链为 STM32CubeCLT 自带的 `arm-none-eabi-gcc 13.3.1`。

选 CubeMX + CMake 而非纯寄存器 IDE 工程，是为了让时钟树与外设配置可复核，并让任何机器 `cmake --build` 即可复现编译，不依赖本地 IDE 配置。

## 电机驱动与引脚分配

驱动每个通道有 IN1、IN2 与 STBY 三根控制线：IN1 接定时器 PWM 调速，IN2 接 GPIO 定方向（高 = 反转），STBY 上电拉高，否则芯片待机、输出全关。

这是**符号-幅值控制**：转速由占空比决定、转向由 IN2 电平决定，同一时刻只有一路 PWM 动作，逻辑简单且不会出现两路同时导通的直通风险。

| 电机 | IN1（PWM） | IN2（方向） | 使能 |
| --- | --- | --- | --- |
| FL 左前 | PA8 / TIM1_CH1 | PB12 | STBY1 = PB0（前级 FL+FR） |
| FR 右前 | PA9 / TIM1_CH2 | PB13 | STBY1 = PB0 |
| BL 左后 | PA10 / TIM1_CH3 | PB14 | STBY2 = PB1（后级 BL+BR） |
| BR 右后 | PA11 / TIM1_CH4 | PB15 | STBY2 = PB1 |

PWM 参数：TIM1，预分频 0，自动重装 3599 → **72 MHz / 3600 = 20 kHz**。取 20 kHz 是因为高于人耳上限（电机不啸叫），且 3600 级分辨率在低速段够用。

> **注意**：TIM1 是高级定时器，除启动 PWM 外还必须置位 **MOE（BDTR 寄存器）**，否则四路通道全部无波形。

## 电源与接口定义

### 电源

- 电池组经 DC 座输入，板上网络标注 `+12V` / `GND`；
- 板载两级降压：LM2575S-5.0（Buck）出 `+5V` 供 PS2 接收器与排针，再经 AMS1117-ADJ（LDO）出 `+3.3V` 供主控；
- 按手册 3.2，整机只有**一个供电模块**、额定电压不超过 7.4 V；无线继电器串在电池与底盘电源之间，用于 10 m 内独立切断动力。

> ⚠️ 板面丝印为 `+12V`，而方案里的 2 节 18650 标称 7.4 V（满电 8.4 V）。接线前需确认实际电池组电压与是否存在升压环节（见待确认项 X3）。

### 接口

| 接口 | 位置 | 定义 |
| --- | --- | --- |
| H1 | 车头左 | 1 NC、2 FL_IN2、3 FL_IN1、4 STBY1、5 FR_IN1、6 FR_IN2、7 NC、8 GND |
| H2 | 车头右 | 1 +12V、2 NC、3 GND、4 FL_O1、5 FL_O2、6 FR_O2、7 FR_O1、8 GND |
| H3 | 车尾左 | 1 NC、2 BL_IN2、3 BL_IN1、4 STBY2、5 BR_IN1、6 BR_IN2、7 NC、8 GND |
| H4 | 车尾右 | 1 +12V、2 NC、3 GND、4 BL_O1、5 BL_O2、6 BR_O2、7 BR_O1、8 GND |
| U2 | PS2 接收器 | 1 CLK、2 CS、3 CMD、4 DI、5 +5V、6 GND |
| U4~U7 | 电机端子 | KF301-2P：FL / FR / BL / BR 各一组 O1、O2 |

## 从「照抄常见接法」到对齐实物

工程最初按通用 STM32F103 开发板的习惯配置：电机 PWM 用 TIM2（PA0~PA3）与 TIM3（PA6/PA7/PB0/PB1），PS2 用 SPI1 重映射到 PB3~PB6。这套配置在本队打样的板子上完全对不上——板上的 PB3~PB6 是空脚，PA6/PA7 接 PS2 的 CS/CLK，PB0/PB1 接 STBY，电机实际接在 PA8~PA11 与 PB12~PB15。按原配置烧录，PWM 全打在通讯线与使能脚上，四轮拿不到任何信号。

修正方式是**改软件不改板**：PCB 已打样，改板成本远高于改固件；把板级初始化从 `tim.c` 剥离到 `Chassis.cpp`，用 TIM1 四通道输出 PWM，停用 `MX_TIM2_Init` / `MX_TIM3_Init` / `MX_SPI1_Init`。

遗留约定：`.ioc` 仍是旧配置，**不要用 CubeMX 重新生成代码**，否则会覆盖上述修正。详细排查过程见文档 [04](./04-开发日志与问题排查.md)。
