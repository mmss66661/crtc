# 03 PS2 手柄遥控

## PS2 手柄通信协议

PS2 接收器与主控之间是标准的 **SPI 类同步串行协议**，一次完整读手柄需要连续收发 **9 个字节**：

| 字节 | 方向 | 内容 |
| --- | --- | --- |
| 0 | 发送 | `0x01`，起始命令 |
| 1 | 发送 | `0x42`，请求数据（进入「读取全部按键与摇杆」模式） |
| 2 | 发送 | `0x00` |
| 3 | 接收 | 按键低字节（Select、L3、R3、Start、↑、→、↓、←） |
| 4 | 接收 | 按键高字节（L2、R2、L1、R1、△、○、×、□） |
| 5 | 接收 | 右摇杆 X |
| 6 | 接收 | 右摇杆 Y |
| 7 | 接收 | 左摇杆 X |
| 8 | 接收 | 左摇杆 Y |

时序要求：拉低 CS 后延时约 10 μs 再开始发送；字节之间需要约 60 μs 的间隔让手柄处理。摇杆为 8 位无符号数，0~255，中位 128。

**实现方式**：`PS2::read()` 用 DWT 周期计数器做微秒级延时（`delay_us`），利用 `HAL_RCC_GetHCLKFreq()` 换算出每微秒的节拍数，比 `HAL_Delay()`（毫秒级）精度高得多，也不占用定时器资源。

```cpp
static void delay_us(uint32_t us) {
  uint32_t start = DWT->CYCCNT;
  uint32_t ticks = us * (HAL_RCC_GetHCLKFreq() / 1000000U);
  while ((DWT->CYCCNT - start) < ticks) { }
}
```

按键为**低有效**，读回后统一取反再判断，映射关系如下：

| bit | 按键 | bit | 按键 |
| --- | --- | --- | --- |
| 4 | ↑ | 12 | △ (Y) |
| 5 | → | 13 | ○ (B) |
| 6 | ↓ | 14 | × (A) |
| 7 | ← | 15 | □ (X) |
| 8 | L2 | | |
| 9 | R2 | | |
| 10 | L1 | | |
| 11 | R1 | | |

摇杆处理：读到的原始值减去 128 转为 -128~+127，再作为线速度与转向量送入 `update()`：

```c
update((float)(-ps2Data.ly), (float)(ps2Data.lx));
```

左摇杆 Y 轴控制前后（取反是因为手柄前推时数值减小），左摇杆 X 轴控制转向。

### 阻塞点：引脚与 SPI1 硬件功能不匹配

板上 PS2 接收器接在 **PA4~PA7**，而原代码使用的是 SPI1 **重映射**后的 PB3~PB6——这四个脚在板子上是空脚。

更关键的是，即使是 PA4~PA7，其信号分配与 SPI1 的硬件固定功能也对不上：

| PS2 信号 | 板上引脚 | SPI1 该脚的硬件功能 | 是否匹配 |
| --- | --- | --- | --- |
| CLK | PA7 | MOSI | ✗ |
| CS | PA6 | MISO | ✗ |
| CMD（主→从） | PA5 | SCK | ✗ |
| DI（从→主） | PA4 | NSS | ✗ |

F103 的 SPI1 固定映射是 `PA4=NSS、PA5=SCK、PA6=MISO、PA7=MOSI`。板上把 CLK 与 CMD 正好接反，DI 又落到了 NSS 上——**这意味着无法使用硬件 SPI**。

### 解决方案：软件模拟时序（bit-bang）

PS2 协议速率很低（字节间隔 60 μs，等效几十 kHz），完全可以用 GPIO 翻转来模拟：

1. 将 PA4~PA7 全部配置为推挽输出（DI 在需要读取的字节切换为输入）；
2. `CLK` 空闲保持高电平（对应 SPI 的 CPOL=1）；
3. 每个 bit：先置数据线，再拉低 CLK → 延时 → 拉高 CLK → 延时；
4. DI 在 CLK 上升沿采样；
5. CS 在整个 9 字节期间保持低电平。

选软件模拟而不是改板飞线，是因为协议速率低、时序容错大，且不需要改动已经打样的 PCB；代价是需要占用 CPU 时间，但一次读手柄约 9 × 8 × 2 μs ≈ 150 μs，在 33 Hz 的主循环里完全可以接受。
