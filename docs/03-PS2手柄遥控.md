# 03 PS2 手柄遥控

## PS2 手柄通信协议

PS2 接收器与主控之间是标准的 **SPI 类同步串行协议**，一次完整读手柄需要连续收发 **9 个字节**：

| 字节 | 方向 | 内容 |
| --- | --- | --- |
| 0 | 发送 | `0x01`，起始命令 |
| 1 | 发送 | `0x42`，请求数据（进入「读取全部按键与摇杆」模式） |
| 2 | 发送 | `0x00` |
| 3 | 接收 | 按键低字节（Select、L3、R3、Start、↑、→、↓、←） |
| 4 | 接收 | 按键高字节（L2、R2、L1、R1、△、○、×、□） |
| 5 | 接收 | 右摇杆 X |
| 6 | 接收 | 右摇杆 Y |
| 7 | 接收 | 左摇杆 X |
| 8 | 接收 | 左摇杆 Y |

时序要求：拉低 CS 后延时约 10 μs 再开始发送；字节之间需要约 60 μs 的间隔让手柄处理。摇杆为 8 位无符号数，0~255，中位 128。

**实现方式**：`PS2::read()` 用 DWT 周期计数器做微秒级延时（`delay_us`），利用 `HAL_RCC_GetHCLKFreq()` 换算出每微秒的节拍数，比 `HAL_Delay()`（毫秒级）精度高得多，也不占用定时器资源。

```cpp
static void delay_us(uint32_t us) {
  uint32_t start = DWT->CYCCNT;
  uint32_t ticks = us * (HAL_RCC_GetHCLKFreq() / 1000000U);
  while ((DWT->CYCCNT - start) < ticks) { }
}
```

按键为**低有效**，读回后统一取反再判断，映射关系如下：

| bit | 按键 | bit | 按键 |
| --- | --- | --- | --- |
| 4 | ↑ | 12 | △ (Y) |
| 5 | → | 13 | ○ (B) |
| 6 | ↓ | 14 | × (A) |
| 7 | ← | 15 | □ (X) |
| 8 | L2 | | |
| 9 | R2 | | |
| 10 | L1 | | |
| 11 | R1 | | |

摇杆处理：读到的原始值减去 128 转为 -128~+127，再按麦轮逆运动学送入 `chassis_move()`。

### 摇杆到麦轮的映射

| 输入 | 含义 | 对应参数 |
| --- | --- | --- |
| 左摇杆 ↑ / ↓ | 前进 / 后退 | `vx = -(ly - 128)` |
| 左摇杆 ← / → | 左移 / 右移 | `vy = (lx - 128)` |
| 右摇杆 ← / → | 逆时针 / 顺时针自转 | `w = -(rx - 128) × 0.5` |

```c
#define JOY_CENTER 128
#define JOY_DEADZONE 12                  /* ±10% 死区 */
#define JOY_SCALE (3600.0f / 128.0f)     /* 摇杆量 → 轮速 */
#define CTRL_PERIOD_MS 20U               /* 50 Hz */

chassis_move(-(float)ly * JOY_SCALE,
              (float)lx * JOY_SCALE,
             -(float)rx * W_SCALE);
```

**为什么左摇杆上下要取反**：手柄前推时 Y 值**减小**（0 在上、255 在下），而 `vx` 以正值为前进，所以取负号。

**为什么旋转要降半速**：原地旋转时四个轮子反向转动，实际线速度是轮速的两倍，满速旋转非常难控，因此 `W_SCALE` 取 `JOY_SCALE` 的一半。

**为什么要做死区**：电位器式摇杆回中后读数在 128 附近抖动（通常 ±5~10），若不处理，车会持续收到一个很小的前进量，出现「没碰摇杆却慢慢爬」的现象。死区取 ±12（约 10% 量程），既能滤掉抖动，又不影响正常操作。

## 实现方式：软件模拟 SPI 时序（bit-bang）

### 为什么不能用硬件 SPI

板上 PS2 接收器接在 **PA4~PA7**，而原代码使用的是 SPI1 **重映射**后的 PB3~PB6——这四个脚在板子上是空脚。

更关键的是，即使是 PA4~PA7，其信号分配与 SPI1 的硬件固定功能也对不上：

| PS2 信号 | 板上引脚 | SPI1 该脚的硬件功能 | 是否匹配 |
| --- | --- | --- | --- |
| CLK | PA7 | MOSI | ✗ |
| CS | PA6 | MISO | ✗ |
| CMD（主→从） | PA5 | SCK | ✗ |
| DI（从→主） | PA4 | NSS | ✗ |

F103 的 SPI1 固定映射是 `PA4=NSS、PA5=SCK、PA6=MISO、PA7=MOSI`。板上把 CLK 与 CMD 正好接反，DI 又落到了 NSS 上——**这意味着无法使用硬件 SPI**。

### 时序实现

PS2 协议速率很低，完全可以用 GPIO 翻转模拟：

- **CLK** 空闲高电平（对应 SPI 的 CPOL=1）；
- 每个 bit **LSB 先行**：先建立 CMD 数据 → 拉低 CLK → 延时 → 拉高 CLK（此沿采样 DI）→ 延时；
- 半周期 3 μs，等效约 166 kHz，低于手柄 250 kHz 上限，留足余量；
- 字节之间留 30 μs；
- **CS 在整个 9 字节期间保持低电平**，发送前延时 10 μs。

微秒级延时仍用 DWT 周期计数器实现——`HAL_Delay()` 是毫秒级，精度不够；而每次读手柄要 9 字节 × 8 bit，用定时器又太浪费。

选软件模拟而不是改板飞线，是因为协议速率低、时序容错大，且不需要改动已经打样的 PCB。代价是需要占用 CPU 时间：一次读手柄约 9 × 8 × 6 μs ≈ 430 μs，在 50 Hz 的控制周期里完全可以接受。

### 模拟模式握手

只有**模拟模式**下手柄才返回摇杆数据（数字模式摇杆字节固定为 `0xFF`）。`PS2::init()` 在上电 300 ms 后发送标准三段命令：

```
进入配置  01 43 00 01 00 00 00 00 00
设置模式  01 44 00 01 03 00 00 00 00   ← 0x03 = 模拟模式
退出配置  01 43 00 00 5A 5A 5A 5A 5A
```

### 在线检测与掉线保护

```c
uint8_t mode = rx[1];   /* 0x41 数字 / 0x73 模拟 / 0x79 配置 */
online_ = (mode == 0x41 || mode == 0x73 || mode == 0x79);
```

- `read()` 在模式字节非法时返回 `false`（修复了原实现「恒返回 true、`online_` 从未赋值」的缺陷）；
- 主循环维护失败计数，连续 **5 次**读失败就 `chassis_move(0,0,0)` 停车，避免手柄断连后车保持最后速度冲出去。

## 当前状态与待验证项

代码已实现并编译通过（FLASH 12592 B / 19.21%），等待实测。

需要确认的三点：

1. **手柄是否被正确识别**：若 `read()` 一直返回 `false`，先检查接收器供电（板上为 +5 V）与 CS/CLK 接线；
2. **左右横移方向**：取决于麦轮辊子朝向，若左推摇杆车却右移，把 `vy` 的符号取反即可；
3. **旋转方向**：若右摇杆右推车却逆时针转，同理取反 `w` 的符号。

实测通过后即可录制「车体与 PS2 手柄同时出镜」的视频，补齐「底盘运动（单一 / 全部）」两项基础功能指标。
