# 03 PS2 手柄遥控

## 通信协议

PS2 接收器与主控之间是 **SPI 类同步串行协议**，一次完整读手柄需连续收发 **9 个字节**：

| 字节 | 方向 | 内容 |
| --- | --- | --- |
| 0 | 发送 | `0x01`，起始命令 |
| 1 | 发送 | `0x42`，请求数据 |
| 2 | 发送 | `0x00` |
| 3 | 接收 | 按键低字节（Select、L3、R3、Start、↑、→、↓、←） |
| 4 | 接收 | 按键高字节（L2、R2、L1、R1、△、○、×、□） |
| 5 / 6 | 接收 | 右摇杆 X / Y |
| 7 / 8 | 接收 | 左摇杆 X / Y |

拉低 CS 后延时约 10 μs 再发送，字节间留约 60 μs 供手柄处理；摇杆为 8 位无符号数 0~255，中位 128。

`PS2::read()` 用 DWT 周期计数器做微秒级延时，精度远高于 `HAL_Delay()`，也不占定时器资源：

```cpp
static void delay_us(uint32_t us) {
  uint32_t start = DWT->CYCCNT;
  uint32_t ticks = us * (HAL_RCC_GetHCLKFreq() / 1000000U);
  while ((DWT->CYCCNT - start) < ticks) { }
}
```

按键为**低有效**，读回后统一取反再判断：

| bit | 按键 | bit | 按键 |
| --- | --- | --- | --- |
| 4 | ↑ | 12 | △ (Y) |
| 5 | → | 13 | ○ (B) |
| 6 | ↓ | 14 | × (A) |
| 7 | ← | 15 | □ (X) |
| 8 / 9 | L2 / R2 | 10 / 11 | L1 / R1 |

摇杆原始值减 128 转为 -128~+127，再作为线速度与转向量送入 `update()`：

```c
update((float)(-ps2Data.ly), (float)(ps2Data.lx));
```

左摇杆 Y 控制前后（取反是因为前推时数值减小），X 控制转向。

### 阻塞点：引脚与 SPI1 硬件功能不匹配

板上 PS2 接在 **PA4~PA7**，原代码却用 SPI1 重映射后的 PB3~PB6——这四个脚在板上是空脚。更关键的是 PA4~PA7 与 SPI1 的固定映射也对不上：

| PS2 信号 | 板上引脚 | SPI1 硬件功能 | 是否匹配 |
| --- | --- | --- | --- |
| CLK | PA7 | MOSI | ✗ |
| CS | PA6 | MISO | ✗ |
| CMD（主→从） | PA5 | SCK | ✗ |
| DI（从→主） | PA4 | NSS | ✗ |

CLK 与 CMD 正好接反，DI 又落在 NSS 上——**无法使用硬件 SPI**。

### 解决方案：软件模拟时序（bit-bang）

PS2 协议速率很低（字节间隔 60 μs，等效几十 kHz），GPIO 翻转完全够用：

1. PA4~PA7 全部配置为推挽输出（DI 在读取字节时切换为输入）；
2. CLK 空闲保持高（对应 CPOL=1）；
3. 每个 bit：先置数据线，再拉低 CLK → 延时 → 拉高 CLK → 采样；
4. DI 在 CLK 上升沿采样，CS 在整个 9 字节期间保持低。

选 bit-bang 而非飞线改板，是因为协议速率低、时序容错大，且不动已打样的 PCB；代价是一次读手柄约 9 × 8 × 2 μs ≈ 150 μs，在 33 Hz 主循环里可以接受。
